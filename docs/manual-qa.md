# 手动验收清单

> 自动化构建与接口测试覆盖不到的部分（麦克风、WASM、真实支付、浏览器行为）都靠这份清单在真机上过一遍。
> 首次录音、连续 20 分钟、充值退款这三类改动至少要跑一遍对应小节。

## 0. 环境准备

- `pnpm build`（含语音模型准备）后再 `pnpm dev`，打开 `http://127.0.0.1:4174/` 或线上 `https://echomind.ljhsu.xin`。
- 用 **Chrome**（目标浏览器），只用一台机器；关闭沉浸式翻译、广告拦截等会改写页面/DOM 的扩展，它们会在控制台制造无关报错。
- 允许麦克风；准备一段能连续说 20 分钟的材料（或循环朗读），不要用静音输入，静音会触发静音提示而不是压力测试。
- 另开一个标签页登录 `https://account.ljhsu.xin/credits`，方便随时对照余额与用量。
- 记录环境：Chrome 版本、macOS 版本、机型、网络（Wi-Fi/有线）、是否首次加载模型。

## 1. 连续 20 分钟稳定性（macOS Chrome）

按顺序做，每步记录时间点、现象与控制台报错：

1. 登录 → 新建「模拟面试」→ 填岗位与 JD → 开始录音。
2. 连续说话 **20 分钟**，中途不停；每 5 分钟留意：
   - 波形/电平是否还在动，计时是否连续；
   - 内存（Chrome 任务管理器 `Shift+Esc`，看该标签页）与 CPU 是否稳定增长；
   - 控制台是否出现 `RangeError`、`wasm` 相关错误或 worker 重启日志。
3. 到 20 分钟上限时应提示缓冲已满并停止保留新音频，但不崩、不卡死、不丢已有转写。
4. 结束录音 → 等待收尾转写（15 秒兜底）。若超过 15 秒仍在「正在收尾」但最终结果随后到达，界面应自动恢复，不需要手动刷新。
5. 用「重新转写」跑一次整段音频（最长 10 分钟超时）：确认结果替换待确认回答，界面不停在 `finishing`。
6. 确认回答 → 生成逐题评价与整场分析 → 打开报告；检查评估内容只来自语义稿、语气词/停顿只作为参考指标。
7. 报告页停留 2 分钟，确认无内存暴涨；再返回历史列表，该练习应已保存。

**通过标准**：全程无崩溃、无白屏、无「正在收尾」永久卡住、音频不出本机（Network 里没有音频请求），历史与积分记录完整。

## 2. 录音与转写边界

- 录音中切换练习、刷新页面、关闭标签页：不应把旧录音写进新练习；已有历史应在 `pagehide` 时落盘。
- 拔掉麦克风/切走蓝牙设备：应给出提示并可重新授权，不出现永久 `loading`。
- 拒绝麦克风权限后再次允许：`授权并刷新设备` 能恢复。
- 网络断开时录音：转写仍应在本机进行，只影响模型调用（提示同步失败/模型失败，可重试）。

## 3. 账号、同步与积分

- 未登录时点「新建练习」应跳转登录；已完成报告仍可只读查看。
- 登录后练习历史同步到该账号；换一台设备/无痕窗口登录同一账号应能看到。
- 本机遗留匿名历史会提示导入，导入后匿名列表清空。
- 头部积分数字与 `account.ljhsu.xin/credits` 一致；跑一次练习后两边同时减少。
- 「积分与用量」弹窗：刷新已改为「充值」，点它应打开设置里的模型设置充值区。
- 点头像/昵称应在新标签页打开 `https://account.ljhsu.xin/account`。
- 充值：套餐 100/1000/5000 与自定义额度（最低 50、最高 1,000,000）各下一单最小额；支付成功后两边余额同时增加；`https://echomind.ljhsu.xin/?recharge=500` 应直接打开充值区并预填 500（未登录会先登录再回跳）。

## 4. 退款

- 账号中心 `/credits` →「申请退款」→ 勾选同意后提交，状态变「待审核」；同一时间不能再次申请。
- 管理员（`role='admin'`）打开 `https://account.ljhsu.xin/admin/refunds`：
  - 列表可筛选/翻页，能展开订单级明细；
  - 「通过并退款」弹金额确认，提交后明细变「已退款」并带渠道单号；
  - 到支付宝商家后台核对退款单号与金额。
- 失败分支：先停掉/改坏退款通道配置，审核后应标记「部分失败」并给出原因；恢复后点「重试失败项」只重试失败订单，已退款的不会重复处理。
- 页面顶部「对账」应显示最近一次结果；点「立即对账」后仍为「余额与台账一致」。

## 5. 记录与回归

- 把每一步的通过/失败、控制台报错原文、Network 里异常请求、耗时与内存数据记到 PR/issue 里；失败项要能复现（哪个步骤、第几分钟）。
- 改动涉及计费、退款、同步、录音任一路径时，先跑 `node scripts/import-credits.mjs --remote`（默认 dry-run）确认账号中心余额与本地记录仍然一致。
